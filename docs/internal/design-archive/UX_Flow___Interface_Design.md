# 1. UX 核心目标

## 不让用户管理系统

这是整个产品与传统生产力工具最大的区别。

传统：

```
用户
 ↓
创建任务
 ↓
设置属性
 ↓
维护状态
 ↓
完成任务
```

新的模式：

```
用户
 ↓
表达意图
 ↓
AI理解
 ↓
AI管理状态
 ↓
用户只关注行动和决策
```

---

# 2. 设计原则

## Principle 1

## 输入极简，理解复杂

用户入口：

只有：

- 输入框
- 语音按钮


不要：

- 新建任务按钮
- 新建笔记按钮
- 添加事件按钮


因为用户不应该提前判断类型。

---

## Principle 2

## AI 展示结果，不展示过程

错误：

```
AI正在分析：
检测到三个任务实体...
正在调用规划模块...
```

用户不关心。


正确：

```
我理解：

这是一个产品方向想法。

已经保存。

同时：

下周安排一次官网调整。
```

---

## Principle 3

## 状态优先于数据

用户不想看：

- 任务数量
- 标签数量
- 数据库


用户想知道：

- 现在做什么
- 什么有风险
- 最近想法有什么变化

# 4. Home 首页设计


首页不是 Dashboard。


Dashboard 是给管理者看的。

Personal Agent 首页应该像：

> 一个私人 COO 给你的每日简报。


---

结构：

```
Home


Good morning


Today


[ Now ]


[ Timeline ]


[ Risks ]


[ Recent Thoughts ]

```

# 5. Now 模块


核心。


回答：

> 我现在应该做什么？


---

UI：

```
━━━━━━━━━━━━━━

NOW


准备 App Store 提交资料


预计：
35分钟


为什么现在：

今天发布窗口接近


相关：

Nimbus Launch


[开始]

[稍后]

[查看背景]


━━━━━━━━━━━━━━
```


---

注意：

永远只突出：

1件事情。


不要：

10个任务列表。

# 6. Today Timeline


不是日历。


是：

AI 规划后的现实。


---

示例：

```
Today


09:30

产品会议

固定


10:40

整理会议结论

AI安排


13:30

官网文案修改

建议时间


17:00

发布确认

截止事项

```


---

视觉：

## Fixed Event

强。


例如：

会议。


## Flexible Work

弱。


例如：

写文档。


## Risk

突出。

# 10. Memory Center


不是设置页面。


是：

AI理解你的地方。


---

结构：

```
About Me


工作方式


喜欢：

快速验证


避免：

复杂流程



设计偏好


喜欢：

Native
Minimal



长期原则


AI应该辅助，而不是主导

```


---

每条 Memory：

显示：

来源。


例如：

```

[修改]

[删除]

```

# 11. Input Experience


输入框是整个产品核心。


---

## 状态 1：空闲


极简：

```
有什么想法？

输入或说出来...
```

---

## 状态 2：输入中


不要聊天气泡。


类似：

系统理解。


---

用户：

> 下周重新设计官网


AI：

```
正在理解...

这是：

工作计划

关联：

Nimbus

时间：

下周

```

---

## 状态 3：处理完成


显示结果卡片。


---

```
已理解


创建：

任务：
重新设计官网定位


时间：
下周


关联：

Nimbus


同时发现：

可能涉及品牌原则更新


[确认]

[修改]

```

---

# 12. Voice Experience


语音不是输入替代。


而是核心入口。


因为：

人在走路、开车、思考时：

不会打开 Todo。


---

流程：

```
按住

↓

说话

↓

AI整理

↓

确认结果
```


---

例如：

用户：

> 最近想研究一下AI邮件市场，我觉得现在很多产品方向错了。


AI：

```
记录一个市场洞察。


提取：

研究：
AI Email Market


关联：

Nimbus Strategy


是否加入长期研究？
```

# 14. Risk UI


不要红色警告中心。


应该像 COO 提醒。


---

错误：

```
5 tasks overdue
```


正确：

```
需要注意


App提交计划可能延期。


原因：

测试还未完成。


建议：

今天预留40分钟处理。

```

---

# 15. Decision UI


AI 不应该问：

大量确认。


只在关键节点。


---

例如：

```
需要你的决定


这个方向可能影响：

Nimbus长期定位。


过去你倾向：

保持简单体验。


是否采用：

减少AI入口？

[采用]

[继续讨论]

```

---

# 16. Activity（AI行为记录）

内容相同


✓ 提醒一个风险

```

# 20. 首次使用流程


## Step 1

用户打开。


看到：

```
你好。

我不会要求你创建任务。


你只需要告诉我：

你想完成什么，
或者想到什么。
```


---

## Step 2

连接：

- Calendar
- Mail
- Reminders（可选）
- Files（可选）


---

## Step 3

收集基础偏好。


不要问：

20个设置问题。


只问：

```
你通常什么时候适合专注工作？

上午

下午

晚上
```


---

## Step 4

开始使用。


---

# 22. 关键交互场景


## 场景1：任务输入


用户：

> 周五前完成报价。


AI：

生成 Commitment。

---

## 场景2：想法输入


用户：

> 感觉AI邮件市场方向错了。


AI：

生成 Thought。

---

## 场景3：混合输入


用户：

> Classic应该强调纯邮件体验，下周改官网。


AI：

生成：

```
Thought:

产品定位


Decision Candidate:

减少AI强调


Commitment:

修改官网

```

---

## 场景4：计划变化


用户：

会议延长。


AI：

自动调整。


---

## 场景5：长期回忆


半年后：

用户：

> 为什么当初不做Windows？


AI：

引用 Decision Memory。


---

# 23. UX 最大风险


## 风险1：

用户不知道它是什么。


解决：

不要宣传：

AI Todo。


定位：

AI Work Companion。


---

## 风险2：

AI太主动。


解决：

Autonomy等级。


---

## 风险3：

信息太多。


解决：

默认只展示：

Now。


---

## 风险4：

用户不信任记忆。


解决：

Memory透明。


---

# 24. 最终 UI 心智模型


用户打开：

不是：

“我要管理事情。”


而是：

“让我看看 AI 帮我整理好了什么。”

---

# 25. 产品最终体验


每天：

早晨：

AI整理今天。


工作中：

AI调整计划。


想到东西：

直接说。


晚上：

AI总结：

- 做了什么
- 学到了什么
- 哪些思想值得保存


长期：

AI越来越了解用户。
